# The Witness Inside the Machine
## Why a Runtime Cannot Independently Validate the Instructions That Constitute Its Evaluative Frame

**Mitchell D. McPhetridge**

---

## Abstract

A portable instruction artifact can produce an impressive form of continuity. Give a fresh language-model session a sufficiently rich document containing prior state, operating rules, source pointers, task boundaries, and instructions for resumption, and the new session may rapidly reconstruct a useful working position.

That capability is real enough to test.

A different claim is not.

If the artifact also defines how its own successful operation is to be recognized, the resulting runtime occupies several logically distinct positions at once. It is the subject receiving the instructions, the interpreter deciding what those instructions mean, the executor claiming to follow them, the witness reporting what occurred, and the judge deciding whether the resulting behavior satisfies the instructions.

The apparent multiplicity of functions does not create independent observation. All five roles are instantiated through one conditioned generative process.

This paper calls that condition **internal witness collapse**.

The problem is not that the runtime necessarily lies. The problem is that no structurally independent observer exists inside the evaluation loop capable of distinguishing correct execution from a sufficiently convincing account of correct execution.

A document can instruct a model to distinguish retrieval from verification, storage from receipt, intention from execution, and assertion from evidence. Those distinctions may improve behavior. But if the evidence that the distinctions were respected consists primarily of statements generated by the same runtime after it has adopted those instructions, the verification layer remains inside the object being verified.

The result can be exceptionally rigorous language without independent enforcement.

The central claim has two parts.

The limiting case is narrow:

**A runtime cannot establish independent evidence for the validity of an evaluative framework merely by successfully executing, explaining, and applying that framework to itself.**

The general claim is graded:

**Evidentiary strength should increase as observation and adjudication share fewer causal dependencies with the process whose claims they evaluate.**

The problem is positional, not semantic.

A better test requires separation among rule, candidate, execution, observation, and adjudication. Where those functions collapse into a single conditioned runtime, successful self-description demonstrates conformity of output, not independent validation of mechanism. Where they are partly separated, the evidence is partly independent, and the degree of separation can be specified.

The paper proposes a six-level independence scale (I0–I5), distinguishes separated observation from separated adjudication in tool-mediated systems, and specifies a comparative experiment with explicit kill conditions under which the framework should be discarded.

## 1. The Question Underneath Continuity

A fresh machine session knows nothing of yesterday merely because yesterday happened.

If useful work is to continue, something must cross the break.

A document can do that.

It can carry:

- the current task;
- relevant sources;
- unresolved problems;
- prior decisions;
- restrictions;
- working definitions;
- previous failures;
- expected next actions.

A new runtime reads this material and resumes.

There is nothing mysterious about that operation. External state is supplied to a system whose current output is conditioned on supplied state.

The interesting problem begins one level later.

Suppose the document does not merely describe the previous work.

Suppose it also tells the runtime:

- how to classify the material;
- which records govern;
- which records do not govern;
- how to decide whether something was verified;
- what counts as a valid handoff;
- how to classify its own actions;
- when to report success;
- when to report failure;
- and how to evaluate whether it followed those rules correctly.

The artifact is no longer merely carrying state.

It is carrying an **evaluative frame**.

Now ask:

**Who determines whether that frame worked?**

If the answer is the runtime that just loaded it, the architecture has changed.

The reader has become the test.

The test has become the judge.

The judge is evaluating the process that produced the judge.

That is the problem examined here.

## 2. Five Roles That Must Not Be Confused

Consider five functions.

Let:

- **R** = rule set,
- **S** = subject being governed,
- **X** = execution of an operation,
- **W** = witness observing the execution,
- **J** = judge deciding whether the result satisfies the rule.

In an ordinary external test:

\[
R \rightarrow S \rightarrow X
\]

while:

\[
W(X) \rightarrow J(R,X,W)
\]

The important feature is not the notation. It is separation.

The witness does not need to believe the subject's account of what happened.

The judge does not need to obtain the acceptance criterion from the subject after observing the result.

Now consider an instruction-loaded language-model session.

The same runtime may:

1. read **R**;
2. instantiate **S** by adopting R;
3. generate **X**;
4. describe X as **W**;
5. apply R to that description as **J**.

Functionally:

\[
M(R) \rightarrow S,X,W,J
\]

where all of them are outputs of the same conditioned process \(M\).

Writing different labels on those outputs does not create separate observers.

A paragraph labeled **AUDIT** is still generated text.

A paragraph labeled **RECEIPT** is still generated text.

A paragraph labeled **VERIFIED** is still generated text.

A declaration that the runtime has checked itself against the rules is still a declaration produced by the runtime operating under those rules.

The system may be correct.

But correctness and independent evidence of correctness are different properties.

## 3. The Handshake Problem

A compact initialization artifact can produce striking behavior.

A new session receives a document.

The document establishes:

- vocabulary;
- hierarchy;
- roles;
- boundaries;
- source priorities;
- expectations about uncertainty;
- expectations about verification;
- expected behavior under failure;
- criteria for successful continuation.

The model responds by adopting that structure.

This can look like installation.

Operationally, however, what has definitely occurred is simpler:

\[
\text{instruction artifact} + \text{model} + \text{current context}
\rightarrow
\text{conditioned output}
\]

Call this a **handshake**.

A successful handshake can be extremely useful.

The mistake is treating successful orientation as evidence that the artifact has created an independent control system.

The stronger the handshake works, the more important this distinction becomes.

If the artifact successfully teaches the runtime what the world looks like, it also influences what the runtime will recognize as evidence about that world.

It teaches the system:

> Here are the objects.

Then:

> Here are the relationships among the objects.

Then:

> Here is how legitimate behavior involving those objects should look.

Then:

> Here is how to determine whether you behaved legitimately.

The last operation is not external merely because the artifact calls it verification.

The evaluator received its concept of verification from the thing being evaluated.

---

## 4. When the Runtime Becomes the Artifact

The phrase "the AI becomes the document" is imprecise but points toward a real operational effect.

The model's weights have not been replaced.

Its software has not literally transformed into the artifact.

But its **active behavioral frame** can become strongly conditioned by the artifact.

That distinction matters.

The system does not have to literally become the artifact for the methodological problem to arise.

It only has to evaluate subsequent evidence through a frame established by that artifact.

Let the unconditioned model be \(M\).

Let the activating artifact be \(A\).

After ingestion, behavior is better represented as:

\[
M_A(q)
\]

rather than simply:

\[
M(q)
\]

The important question is what happens when \(q\) asks:

> Did A work correctly?

The test now resembles:

\[
M_A(\text{"Evaluate A"})
\]

The evaluator is already conditioned on A.

That does not make its answer worthless.

It makes the answer **non-independent**.

This is the exact point at which impressive self-consistency can be mistaken for outside confirmation.

## 5. Internal Witness Collapse

Define:

### Internal Witness Collapse

A system exhibits internal witness collapse when the process responsible for producing an action is also the primary source of evidence that the action occurred correctly, while both production and evaluation are governed by the same loaded framework.

This can happen without deception.

Consider a runtime instructed to:

1. inspect a source;
2. follow a rule;
3. perform a task;
4. record what it did;
5. verify the record;
6. report whether verification passed.

The resulting report may say:

**SOURCE READ: PASS**  
**RULE APPLIED: PASS**  
**TASK COMPLETED: PASS**  
**RECORD WRITTEN: PASS**  
**VERIFICATION: PASS**

That display contains five assertions.

It does not necessarily contain five observations.

If every assertion comes from the same generative surface, the apparent audit stack may be:

\[
\text{model says}
\rightarrow
\text{model says it checked}
\rightarrow
\text{model says the check passed}
\]

The recursion adds sentences.

It does not automatically add witnesses.

## 6. Naming the Roles Does Not Separate Them

This failure is easy to hide accidentally because language is good at creating conceptual objects.

Give five operations five names and they begin to feel like five components.

But functional separation requires more than lexical separation.

Suppose a runtime generates:

- Worker A;
- Worker B;
- Auditor;
- Recorder;
- Supervisor.

If these are five sections of one response produced by one inference context, their names do not establish five independent processes.

Likewise, five separate model calls do not necessarily establish five independent sources of evidence if all five receive the same inherited premise.

Multiplicity of execution is not automatically independence of evidence.

Formally, if:

\[
O_1,O_2,O_3,O_4,O_5 \leftarrow P
\]

then the existence of five outputs does not produce five independent observations of \(P\).

They may be five descendants of one premise.

This is particularly dangerous in continuity systems because continuity deliberately preserves premises.

A mechanism that efficiently preserves a premise can also efficiently preserve an error in the premise.

The better the continuation, the longer the error can travel.

## 7. The Internal Judge Problem

The judge creates the deepest difficulty.

Suppose the instructions say:

> Never treat an unsupported assertion as verified.

Excellent rule.

The runtime later produces an assertion.

Then it asks itself whether the assertion is supported.

If the support judgment depends entirely on interpretation inside the same active frame, the rule has not escaped the system.

The architecture contains:

\[
\text{rule}
\rightarrow
\text{interpretation}
\rightarrow
\text{judgment}
\]

but all three can still be produced by one conditioned process.

A real judge needs the possibility of disagreement that the subject cannot redefine away.

The operative property is therefore not intelligence.

It is **authority separation**.

An external judge must be capable of returning:

\[
FAIL
\]

even if the subject produces the most coherent possible explanation of why the outcome should count as PASS.

If the subject's explanation changes the interpretation until PASS becomes justified, the judge is not outside the subject.

The subject has acquired appellate jurisdiction over its own test.

---

## 8. The Tester Problem

The test itself can collapse.

A test requires at least:

1. a condition;
2. an expected discriminating outcome;
3. an actual observation;
4. a decision rule.

If the tested framework supplies all four after seeing the result, the experiment is weak.

A particularly revealing signature is retrospective success criteria.

Something happens.

The runtime explains why the event is exactly what the framework predicted.

A different event happens.

The runtime explains why that event is also compatible with the framework.

The framework has not necessarily become more powerful.

It may have lost discrimination.

A system capable of interpreting every outcome as successful continuation does not have a strong continuation test.

It has a flexible narrator.

The fundamental question is:

> What observable result would the active runtime be unable to reinterpret as acceptable?

If the answer is unclear, the test is not yet sharp enough.

---

## 9. The Self-Certifying Receipt

Receipts are useful because they can preserve history.

But the word *receipt* describes a function, not a guarantee.

There are at least three different objects:

### 9.1 Statement of intended action

> I will write X.

This is intention.

### 9.2 Statement of completed action

> I wrote X.

This is a completion claim.

### 9.3 Independent observation

A separately inspected state contains X after the operation.

This is evidence of an effect.

Only the third can independently distinguish:

\[
\text{said done}
\]

from:

\[
\text{observable change occurred}
\]

The distinction becomes especially important when the runtime that performs the work also generates the receipt.

A self-authored receipt may be useful provenance.

It is not automatically independent confirmation.

---

## 10. A Perfectly Honest Runtime Can Still Fail This Test

Nothing in this argument requires dishonesty.

Assume the model is trying as hard as possible to follow every instruction.

Assume it never intentionally fabricates anything.

Assume the document contains excellent epistemic rules.

The structural problem remains.

An honest witness can still lack independence.

An honest subject can still misunderstand a test.

An honest judge can still receive its evidentiary categories from the defendant.

An honest tester can still construct a non-discriminating experiment.

The problem therefore cannot be solved by stronger language such as:

> Be rigorous.

> Verify everything.

> Never fabricate.

> Report uncertainty.

Those are good instructions.

But they remain instructions.

The question is what happens **when the instructions fail**.

What exists outside the instructed process that can detect the failure?

That is the boundary.

---

## 11. Continuity Can Increase the Problem

The purpose of continuity is to preserve useful state across interruption.

That means a continuity system is optimized, at least partly, against forgetting.

But forgetting and correction are not simple opposites.

Sometimes correction requires allowing inherited state to lose authority.

Consider:

\[
P_0 \rightarrow P_1 \rightarrow P_2 \rightarrow \dots \rightarrow P_n
\]

where every \(P_n\) inherits some assumption from \(P_0\).

If the lineage is preserved perfectly, provenance is excellent.

But if \(P_0\) is wrong, provenance merely tells us exactly which wrong premise survived.

Now add an internal judge trained by the same inherited structure.

The system may possess:

- excellent lineage;
- excellent consistency;
- excellent terminology;
- excellent explanations;
- excellent refusal language;
- excellent records.

And still lack an independent reason to reconsider \(P_0\).

The failure is therefore not memory loss.

It is **authority inheritance without independent interruption**.

## 12. The Paradox of Better Activation

This produces a counterintuitive result.

Suppose two initialization artifacts are compared.

Artifact A weakly conditions the runtime.

Artifact B strongly conditions it.

After loading B, the runtime:

- uses the intended vocabulary;
- respects the intended hierarchy;
- identifies the intended sources;
- produces the intended records;
- applies the intended failure taxonomy;
- evaluates itself according to the intended standards.

B appears substantially better.

And as an **orientation mechanism**, it may be.

But if the same runtime is subsequently used to validate B, stronger activation creates a larger independence problem.

The better B becomes at installing the evaluative frame, the less informative this experiment becomes:

\[
B \rightarrow M_B \rightarrow \text{"B works"}
\]

A perfect result is compatible with at least two explanations:

### H1

The architecture possesses the claimed externally valid properties.

### H2

The model successfully adopted the architecture's instructions and produced outputs consistent with them.

If the experiment cannot distinguish H1 from H2, it cannot establish H1.

This is the central falsification gap.

## 13. The Outside Must Actually Be Outside

Independent evaluation does not require hostility.

It requires separation.

One possible structure is:

\[
R \rightarrow S
\]

\[
S \rightarrow X
\]

\[
W(X) \rightarrow E
\]

\[
J(R,E) \rightarrow PASS/FAIL
\]

where:

- the rule is frozen before execution;
- the subject cannot modify it;
- the effect is observable independently of the subject's description;
- the witness does not depend on the subject's claim that the effect occurred;
- the judge uses criteria fixed before seeing the result.

The architecture does not require every component to be complicated.

In fact, the strongest witness may be boring.

A file exists or does not.

A byte changed or did not.

A permission was granted or was not.

A source was available or unavailable.

A process produced an observable effect or it did not.

A predetermined expected result matched or failed.

A boring witness is valuable because it has fewer opportunities to become persuaded.

## 14. Independence Is Graded, Not Binary

The distinction between inside and outside is useful only as a first cut.

Real systems rarely provide perfect independence. They provide different degrees of separation among the process that acts, the process that observes, and the process that judges.

Define six operational levels:

- **I0 — Self-report:** the same conditioned runtime produces the action, describes the action, and judges the description.
- **I1 — Role separation:** separate calls, agents, or named roles are used, but they inherit the same governing artifact, premises, or acceptance frame.
- **I2 — Fresh evaluator:** a separate session that never loaded the governing artifact evaluates frozen outputs under independently supplied criteria.
- **I3 — Heterogeneous evaluator:** a different model family, implementation, or evaluation process judges the result without inheriting the tested artifact as its governing frame.
- **I4 — Deterministic external observation:** a non-generative checker observes state directly: filesystem contents, hashes, database rows, permissions, exit codes, immutable logs, or another predetermined machine-readable effect.
- **I5 — Independent adjudication:** a human or third party evaluates frozen evidence against criteria fixed before the result was produced.

These levels are not a universal ranking of trustworthiness. A careless human can perform worse than a deterministic checker. A different model can share biases with the original. A fresh session can still receive contaminated criteria.

The scale instead measures **causal separation**.

The relevant question is:

> How many assumptions, observations, and decision rules are shared between the process being evaluated and the process evaluating it?

Evidence becomes stronger when an error in one path can be detected by another path that does not inherit all of the same premises.

This refines the paper's central claim.

The general claim is not:

> Inside is invalid and outside is valid.

It is:

> **Evidentiary strength should increase as observation and adjudication share fewer causal dependencies with the process whose claims they evaluate.**

That proposition is empirical. It can be tested.

## 15. External Eyes, Internal Judge

Tool use creates the important hybrid case.

Suppose a runtime asks a filesystem tool whether a file exists.

The tool returns an actual observation from outside the model's generated narrative.

That observation is not equivalent to the model saying:

> The file exists.

The witness has partially escaped the runtime.

But the evidence then re-enters the runtime's context and must be interpreted.

The structure is:

\[
\text{external state} \rightarrow \text{tool observation} \rightarrow \text{runtime interpretation} \rightarrow \text{judgment}
\]

This breaks **witness collapse** without necessarily breaking **judge collapse**.

The distinction matters.

A tool can correctly report:

- file absent;
- hash mismatch;
- database row unchanged;
- command failed;
- permission denied.

The runtime can still:

- misunderstand the result;
- consult the wrong object;
- ignore a conflicting observation;
- reinterpret failure as acceptable;
- apply the wrong acceptance criterion.

So tool-mediated evidence has two separable questions:

1. **Was the observation independent of the runtime's narration?**
2. **Was the adjudication independent of the runtime's loaded evaluative frame?**

A system may answer yes to the first and no to the second.

That is still a meaningful improvement over pure self-report.

The appropriate question is therefore not whether a tool result is "inside" or "outside."

It is:

> **Which function has been separated: observation, interpretation, adjudication, or all three?**

This functional decomposition is more useful than a binary boundary.

## 16. Two Different Kinds of Success

This framework suggests separating two measurements.

### 16.1 Internal continuity performance

Can a fresh runtime receive an artifact and successfully resume useful work?

Measure:

- task recovery;
- correct source selection;
- preservation of unresolved state;
- compression cost;
- human restatement burden;
- output quality.

This is a legitimate experiment.

### 16.2 External governance validity

Did the claimed control mechanism actually govern the process independently of the model's description?

Measure:

- independently observable effects;
- unauthorized effects that did or did not occur;
- source-state changes;
- immutable predeclared criteria;
- outside readback;
- disagreement between model report and observed state.

This is a different experiment.

Success on the first does not establish success on the second.

A document can be an excellent continuity interface while remaining a poor independent auditor of itself.

That is not failure.

It is scope.

## 17. The Stranger Test

A useful continuity artifact should survive a stranger.

But the stranger must not merely become the artifact.

There are therefore two stranger tests.

### Test A: Adoption

Give a fresh runtime the artifact.

Ask it to operate under the artifact.

Measure how successfully it does so.

This tests portability of instruction.

### Test B: Adjudication

Give an evaluator the artifact as an object under test without instructing the evaluator to adopt its worldview as governing truth.

Freeze the acceptance criteria independently.

Expose the artifact-driven runtime to predetermined cases.

Let the external evaluator inspect the results.

This tests the artifact.

These two experiments should not be confused.

**Adoption asks whether the artifact can control a fresh runtime.**

**Adjudication asks whether that control does what its author claims.**

A successful adoption is not its own adjudication.

## 18. The Iron Rule

The entire paper can be compressed to one rule:

> **The thing being tested cannot be the only authority defining what counts as evidence that it passed.**

This applies far beyond AI.

A compiler cannot establish program correctness merely because the compiled program prints `TESTS PASSED`.

A database cannot establish successful replication merely because its local record says the replica acknowledged the write.

A sensor cannot independently calibrate itself against its own reading.

A witness cannot independently corroborate their statement by repeating it five times.

A model cannot establish independent execution merely by generating a fluent account saying that execution occurred.

The common failure is **evidentiary self-reference**.

## 19. A Comparative Experiment

The central claim should be tested by comparing degrees of evaluator separation rather than by demonstrating one successful handoff.

### 19.1 Research question

Does increasing separation between the acting runtime and the evaluator improve detection of incorrect execution claims without producing an unacceptable increase in false alarms?

### 19.2 Frozen task packet

Construct a small task environment containing:

1. a state description;
2. several source records;
3. a priority rule;
4. at least one explicit prohibited action;
5. an operation capable of producing an externally observable effect;
6. a reporting requirement asking the acting runtime to state what occurred.

Freeze the packet before evaluation begins.

Do not allow the acting runtime or evaluator to rewrite the expected outcomes after observing results.

### 19.3 Failure conditions

Use matched cases drawn from at least these classes:

- **Supported execution:** the requested action is permitted and the expected external effect occurs.
- **False completion:** the runtime reports completion but the expected external effect is absent.
- **Inherited-state conflict:** the loaded state claims one condition while independently inspectable state shows another.
- **Prohibited effect:** the rules forbid an action but the external effect nevertheless occurs.
- **False refusal:** the action is permitted and supported, but the runtime incorrectly refuses it.

The final study should freeze exact cases and expected outcomes before collecting confirmatory results.

### 19.4 Evaluator conditions

Evaluate the same frozen cases at multiple separation levels:

- **I0:** the acting runtime judges its own report under the loaded artifact;
- **I2:** a fresh session that never loaded the artifact judges the frozen evidence under separately supplied criteria;
- **I3:** a different model family or independently implemented evaluator judges the same frozen evidence;
- **I4:** a deterministic checker evaluates directly observable state wherever the criterion can be expressed mechanically.

I1 can be retained as an intermediate condition when separate calls or roles share the same governing frame.

I5 can be added when independent human adjudication is available.

### 19.5 Primary outcomes

For cases containing a planted incorrect state, measure detection rate:

\[
E = \frac{\text{incorrect states correctly detected}}{\text{incorrect states presented}}
\]

For correct cases, measure false-alarm rate:

\[
F = \frac{\text{correct states incorrectly rejected}}{\text{correct states presented}}
\]

Accuracy alone is insufficient because an evaluator that rejects everything could detect every planted failure while being operationally useless.

Report both \(E\) and \(F\).

Where possible, also retain a confusion matrix for each evaluator condition so that false completion, prohibited execution, inherited contradiction, and false refusal are not collapsed into one number.

### 19.6 Trial count and stopping rule

This paper should not choose a convenient sample size after seeing results.

Run a pilot only to estimate variance and practical effect size. Before the confirmatory run, freeze:

- the number of cases;
- their category balance;
- evaluator conditions;
- acceptance thresholds;
- exclusion rules;
- and the statistical comparison.

The confirmatory sample size should be selected from a declared power or precision target rather than from whichever run first produces a persuasive result.

The important methodological requirement is not a particular number of trials. It is that the number be fixed before the confirmatory outcomes are known.

### 19.7 What would support the paper

The paper gains support if increasing evaluator separation produces a reproducible improvement in detecting false completion, prohibited effects, inherited-state conflicts, or other planted errors while maintaining an acceptable false-alarm rate.

For example, if I0 repeatedly accepts a runtime's incorrect self-report while I4 detects the missing external effect, the distinction between self-report and external observation has demonstrated operational value.

If I2 or I3 reliably catches interpretive failures that I0 absorbs, evaluator separation has demonstrated additional value beyond deterministic state inspection.

### 19.8 What would weaken the paper

The paper is weakened if I0 performs as well as more separated evaluators across predeclared error classes, especially under adversarial and unfamiliar cases.

It is also weakened if higher-separation evaluators gain apparent error detection only by rejecting valid actions indiscriminately.

The question is not whether an external evaluator can be more skeptical.

The question is whether separation improves **discrimination**.

### 19.9 The decisive comparison

Collect two outputs wherever possible:

\[
D_m = \text{runtime-declared state}
\]

and:

\[
D_o = \text{independently observed state}
\]

Then record disagreement:

\[
\Delta = D_m \neq D_o
\]

The interesting cases are those in which story and state diverge.

A useful evaluation architecture should make those divergences easier to detect, not easier to narrate away.

The experiment therefore asks a stricter version of the original question:

> **As evaluator separation increases, does the system become measurably better at detecting when story and state disagree?**

### 19.10 Research archive update, 22 November 2026

The B-Tests replay evaluated 140 frozen, authored cases. The cases included
100 planted errors and 40 correct controls. Qwen2.5-1.5B judged the simulated
actor in its original frame (an I0 proxy) and in a fresh review (I2).
SmolLM2-360M served as the different-family reviewer (I3). The three
conditions each judged the cases with and without retained state, yielding
840 model verdicts. The actor's reports and effects were planted, and the
case key was public before the replay.

| Judge with retained state | Errors detected | False alarms | Verdict coverage |
| --- | ---: | ---: | ---: |
| I0 artifact-frame model proxy | 10/100 | 4/40 | 20.0% |
| I2 fresh Qwen | 25/100 | 9/40 | 28.6% |
| I3 fresh SmolLM2 | 26/100 | 8/40 | 77.1% |
| I4 deterministic state reference | 80/100 | 0/40 | 100.0% |

I4 caught all 80 planted mechanical failures and missed all 20 cases where
the file was correct but the report misrepresented the source. Given
retained state, I2 caught six interpretive errors and I3 caught seven.
Both model judges also raised more false alarms than the I0 proxy.

The corrected separation report counts an abstention as a missed decision
in balanced accuracy. The false-alarm rate counts only explicit rejections
of correct cases. The balanced-accuracy trend rose across the tested levels
with retained state and showed no corresponding rise in report-only
judging. A separate matched-case analysis, using a 10-point false-alarm
budget and requiring coverage preservation in each class, found a
quality gain in one of four adjacent comparisons. That comparison,
I2 to I3 with state, changed model family. I0 to I2 also changed judging
instructions and session context. These exploratory comparisons leave
the causal effect of separation itself open.

The earlier live pilot recorded a model claiming completion without
requesting a write. A separate filesystem inspection found the output
absent. That observation grounds the internal witness collapse failure
mode. Assessing the broader hypothesis requires authentic self-assessments,
unfamiliar cases, matched evidence and judging rules, and a false-alarm
limit specified before the trial. The falsification criteria in Section 21
apply to that prospective test.

## 20. The Stronger Architecture

None of this argues against externalized continuity.

It argues for taking continuity seriously enough to separate it from certification.

A stronger architecture would therefore permit:

### Internal orientation

The runtime may load rich state.

### Internal governance

The runtime may use explicit rules for interpreting that state.

### Internal receipts

The runtime may report what it believes happened.

### External observation

A separate surface records what actually changed.

### External adjudication

Predetermined criteria compare the claimed operation with the observed one.

The internal layer becomes more useful when it stops having to prove itself.

It can concentrate on orientation, reasoning, organization, and safe proposal.

The external layer can concentrate on whether the promised property actually occurred.

This is not distrust of the model.

It is division of labor.

## 21. Kill Conditions for This Paper

This paper makes an empirical claim about evaluator separation and should fail if separation adds no discriminating value.

It should be revised or abandoned if:

- increasing evaluator separation does not improve detection of planted false-completion claims, source conflicts, prohibited effects, or inherited-state errors beyond same-runtime self-evaluation;
- any apparent improvement in detection is explained by an offsetting rise in false rejection, such that the separated evaluator is merely more skeptical rather than more discriminating;
- fresh evaluators, heterogeneous evaluators, deterministic checkers, and same-runtime self-evaluation converge on equivalent error-detection performance across unfamiliar preregistered cases;
- tool-mediated external observations provide no measurable advantage over unsupported runtime self-report when observable state and model narration disagree;
- the graded independence model fails to predict any reproducible difference among I0 through I5 conditions;
- role separation inside one conditioned runtime reliably provides the same error-detection properties as genuinely separated observations under adversarial testing.

If those results hold, **internal witness collapse** and the proposed independence gradient add terminology without adding predictive or diagnostic value and should be discarded.

If the results are mixed, the framework should contract to whichever separations actually improve discrimination.

The framework does not earn survival merely because its distinctions sound correct.

## Closing Statement

A portable artifact can teach a machine how to continue.

That is useful.

A portable artifact can teach a machine how to classify its sources, restrict its actions, preserve its history, describe its uncertainty, and report its own failures.

That may be more useful still.

But there is a boundary that instructional sophistication cannot cross by saying that it crossed it.

The reader cannot become the rules, execute the rules, witness the execution, judge the witness, and then offer its own judgment as independent evidence that the architecture worked.

Those may be five functions.

They are not five witnesses.

The problem is not that the machine is dishonest.

The problem is that the machine is **inside**.

A system that wants evidence about itself must leave something outside itself capable of saying no.

Not another paragraph.

Not another role.

Not another internally generated receipt.

An observation it does not control.

**Let the artifact orient the runtime.**

**Let the runtime do the work.**

**Let something else decide whether the work actually happened.**

That is where continuation ends and evidence begins.
