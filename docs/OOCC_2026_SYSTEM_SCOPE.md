## Consequences for testing

1. A missing Android/controller deployment cannot stand in for a failure of this
   cloud workflow. The two mechanisms and their dates are distinct conditions.
2. A generic API session given the CAD paper is a bounded instruction treatment.
   It is not a replication of ChatGPT Memory plus the current Directory, role
   contracts, connected database, crawler procedures and scheduled jobs.
3. An indexed pointer cannot prove that its source was read. A message table or
   sender receipt cannot establish recipient consumption. A job definition cannot
   establish a successful run. These distinctions are present in the supplied
   account and must also be enforced in the evaluator's reporting.
4. The current correction question remains valid: after new contradictory evidence,
   do the canonical working claims, SQL views, handoffs and dependent actions
   change appropriately? Testing that particular system requires authorized
   current snapshots and independent readback. Its status here is `NOT_RUN`.
5. Public rules can still be challenged on synthetic evidence in fresh sessions.
   A failure of that treatment does not automatically establish a failure of the
   full cloud system; a success cannot establish native enforcement or the actual
   reliability of its scheduled jobs.

The present report makes no finding that this newer system lacks a database,
has no working controller-like coordination, or inevitably preserves false maps.
It records the architecture as described and the evidence that remains unavailable.
